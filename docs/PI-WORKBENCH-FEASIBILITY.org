* Feasibility Verdict
:PROPERTIES:
:ID: pi-workbench-feasibility-verdict
:TYPE: decision
:END:

The vision is *feasible*. The Workbench-native ownership decision removes the
upstream transport seam from the critical path.

It decomposes into three tractable layers:

1. *Emacs porcelain* — feasible now. Magit Section/Transient and Pimacs supply
   nearly all interaction primitives.
2. *OTP-inspired supervisor* — feasible now over ordinary =pi --mode rpc=
   processes that Magpi starts and monitors itself.
3. *Normalized intent/attention model* — feasible incrementally from Magpi-owned
   events and journal state; external =pi-subagents= discovery remains incomplete
   but is now an optional backend concern.

Clean control of Magpi-owned attempts uses standard Pi RPC and needs no custom Pi
extension RPC seam. The upstream gaps documented below matter only when importing
or controlling runs owned by another supervisor.

The decisive conclusion is:

#+begin_quote
The hard problem is not rendering the tree. It is preserving exact identity,
authority, acknowledgement, and human attention across process and attempt
boundaries.
#+end_quote

A useful read-only operational-attention prototype can be built immediately.
Exact mutation of arbitrary current-session runs and mission-first workflows must
remain gated.

* Prior Art That Actually Matters
:PROPERTIES:
:ID: pi-workbench-priors
:TYPE: research
:END:

** Magit Section — semantic point and refresh continuity

Primary sources:

- [[https://docs.magit.vc/magit/Refreshing-Buffers.html][Magit: Refreshing Buffers]]
- [[https://docs.magit.vc/magit/Transient-Commands.html][Magit: Transient Commands]]
- [[https://docs.magit.vc/magit-section/magit-section.html][Magit-Section developer manual]]
- local source =magit/lisp/magit-section.el= and =magit/lisp/magit-mode.el=

What is proven:

- a row is a typed section object, not text;
- section identity includes stable values through ancestry;
- point and window start can survive destructive buffer reconstruction;
- explicit visibility survives refresh;
- Transient separates infix intent from suffix execution;
- point supplies a noun and the suffix supplies a verb.

What Pi Workbench should borrow:

- one =target-at-point= accessor for keyboard, mouse, and context menu;
- domain ID as section value;
- transactional rebuild with deterministic fallback when the selected entity
  disappears;
- contextual Transient scope captured for preview and revalidated on execution.

What it must not borrow:

- the assumption that refresh reads one synchronous authoritative store;
- the assumption that a command and its resulting state form one local
  transaction;
- persistent Transient history for owner epochs, capability handles, revisions,
  or sensitive intervention text.

** Gerrit Attention Set — “whose turn is it?” as first-class state

Primary source:

- [[https://gerrit-review.googlesource.com/Documentation/user-attention-set.html][Gerrit Attention Set]]

Gerrit explicitly maintains the people currently expected to act. Replying
moves attention according to deterministic rules; completing, abandoning, or
marking work in progress clears it. The key insight is not the arrow icon. It is
that attention is a maintained turn-taking contract, distinct from review/change
lifecycle.

Workbench implication:

- attention is not “all non-green status”;
- every attention item needs an expected actor, source, reason, and rule for
  leaving/re-entering the set;
- acknowledging is not resolving;
- operators may safely ignore work that does not name them or their role;
- explicit questions outrank inferred staleness.

This is the strongest precedent for making Attention—not Fleet—the default
projection.

** Temporal — typed messages, immutable attempts, durable history

Primary sources:

- [[https://docs.temporal.io/encyclopedia/workflow-message-passing][Temporal: Workflow Message Passing]]
- [[https://docs.temporal.io/workflow-execution/event][Temporal: Event History]]
- [[https://docs.temporal.io/workflow-execution][Temporal: Workflow Execution]]

Temporal distinguishes:

| Temporal concept | Relevant Workbench concept |
|------------------+----------------------------|
| Workflow ID      | durable mission/intent identity |
| Run ID           | immutable execution attempt |
| Query            | read-only inspection, no history mutation |
| Signal           | asynchronous write, no returned result |
| Update           | tracked write with validation and completion/error |
| Event History    | append-only facts used for recovery and audit |

The Query/Signal/Update split is a sharper prior than generic “send command.”
It validates separate Workbench semantics:

- inspect;
- fire-and-track delivery (steer/follow-up);
- request-and-await-operation (stop/resume/decision response);
- effect-observed proof.

The acknowledgement ladder should therefore remain explicit:

#+begin_example
created → accepted/rejected → delivered? → operation completed/failed
        → effect observed or outcome unknown
#+end_example

A durable intent can span immutable attempts. Retry, fork, resume, cancel, and
terminate are distinct verbs, never one “restart.”

** Kubernetes and k9s — identity, revision, watch, and blast radius

Primary sources:

- [[https://kubernetes.io/docs/reference/using-api/api-concepts/#resource-versions][Kubernetes API resource versions and watch]]
- [[https://kubernetes.io/docs/concepts/overview/working-with-objects/names/][Kubernetes object names and UIDs]]
- [[https://k9scli.io/topics/commands/][k9s commands]]

Kubernetes proves the snapshot-plus-watch model:

1. fetch a list with =resourceVersion=;
2. watch changes after that version;
3. reconnect from the last known version when possible;
4. relist when history is too old.

It also proves why display names are unsafe: UID distinguishes incarnations,
while resource version rejects stale mutation.

Workbench implication:

- =(ownerEpoch, target ID, adapterRevision)= is the correct shape;
- a sequence gap or owner replacement invalidates capability handles;
- the buffer keeps stale evidence but disables mutation;
- accepted deletion/stop is not observed terminality;
- exact scope must be previewed before destructive action.

k9s proves the value of a fast, selection-oriented action surface and =?= help.
It also provides a warning: a dense key surface can include both confirmed delete
and unconfirmed force-kill. Workbench should copy its speed, not its blast-radius
shortcuts.

** Argo Workflows — selected-node control and explicit human gates

Primary sources:

- [[https://argo-workflows.readthedocs.io/en/latest/node-field-selector/][Argo node field selectors]]
- [[https://argo-workflows.readthedocs.io/en/latest/walk-through/suspending/][Argo suspending workflows]]
- [[https://argo-workflows.readthedocs.io/en/latest/retries/][Argo retries]]

Argo exposes =resume=, =stop=, and =retry= against selected nodes. Its docs
explicitly distinguish display name from unique node ID/full ancestral name when
siblings collide. Suspend nodes provide a concrete human gate; resume may carry
operator data.

Workbench implication:

- repeated agent roles demand full stable identity;
- retry scope must say child, subtree, attempt, or workflow;
- a paused node should create a typed attention request rather than force the
  human to discover it visually in a graph;
- resume input belongs in a contextual transient and control receipt.

** LangGraph and Agent Inbox — durable interrupts and response schemas

Primary sources:

- [[https://docs.langchain.com/oss/python/langgraph/interrupts][LangGraph interrupts]]
- [[https://github.com/langchain-ai/agent-inbox][LangGraph Agent Inbox]]

LangGraph interrupts persist graph state and wait indefinitely. A =thread_id= is
a persistent cursor; =Command(resume=...)= provides the value returned to the
interrupted node. Agent Inbox standardizes explicit response actions such as
accept, edit, respond, and ignore.

Workbench implication:

- a human request is a typed entity with payload schema and allowed responses;
- response must address a stable interrupt/attention ID;
- durable human latency is normal, not an error timeout;
- resuming from a checkpoint may re-execute code before the interrupt, so replay
  safety and idempotency must be visible;
- the inbox is primary; the graph is a linked diagnostic view.

** Claude Code agent teams — useful interaction, cautionary semantics

Primary source:

- [[https://code.claude.com/docs/en/agent-teams][Claude Code agent teams]]

The current docs show a compact teammate panel where arrow keys select a worker,
=RET= opens its transcript/direct message path, and =ESC= interrupts the selected
turn. Teams also share a task list and direct teammate messaging.

This validates the desired quick “tab to agent, inspect, intervene” feel. But the
feature is explicitly experimental and documents limitations around session
resumption, task coordination, and shutdown. Its task list and panel are useful
UX priors, not durable authority or audit models.

Workbench should borrow:

- addressable idle workers;
- collapsed idle counts while failed/working/selected agents remain visible;
- direct exact-target messaging;
- task ownership as explicit intent.

It should add what the precedent lacks:

- immutable attempt lineage;
- exact delivery/application receipts;
- persistent recovery;
- stale claim/lease semantics;
- owner/version routing.

** Emacs operational modes — supporting rather than governing priors

Additional primary-source families:

- Forge notifications/topics: separate notification state from authoritative
  issue/change state.
- =tabulated-list-mode=/Proced: semantic row IDs survive refresh; process IDs
  alone are too weak for durable identity.
- Compilation mode: append-only live evidence with source navigation and finish
  hooks; never infer control state from parsed transcript text.
- Comint/process filters and sentinels: arbitrary chunk boundaries, reentrancy,
  dead buffers, and late callbacks are normal.
- GUD: execution evidence location and human editing point are separate anchors.

These validate the Workbench rendering and event-pump design, but none is a model
for distributed control authority.

** Pi =main=: host RPC seam remains absent

Checked current public =main= documentation and source:

- [[https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/rpc.md][current RPC documentation]]
- [[https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/docs/extensions.md][current extension documentation]]
- [[https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/modes/rpc/rpc-types.ts][current =RpcCommand= union]]
- [[https://raw.githubusercontent.com/earendil-works/pi/main/packages/coding-agent/src/modes/rpc/rpc-mode.ts][current RPC dispatcher]]

Neither current docs nor source expose =registerRpc=, custom RPC command
registration, or arbitrary extension-defined RPC event registration. Extension
slash commands are callable through =prompt=, and extension UI has a fixed
subprotocol, but neither returns arbitrary structured command data to Pimacs.

Verdict: *Stage 0A blocker confirmed on current public head*.

GitHub issue search surfaced a closely related failure mode—extension slash
commands have no useful output in headless/print mode—but no merged general
structured extension RPC facility. Pi =v0.84.2= release notes do not announce one.

** Pimacs =master=: client machinery exists but remains private

Current =master= still contains private =pimacs--send-command= and private event
subscription tables. It can send any JSON object and dispatch any received event
type, but Pi must first accept/emit those records. This is excellent client
plumbing, not a server seam.

Verdict: *small compatibility adapter feasible now; public Pimacs API still a
productization task*.

** pi-subagents =0.49.0=/=main=: useful RPC, incomplete projection

Verified current npm metadata and current source:

- [[https://registry.npmjs.org/pi-subagents/latest][npm latest metadata]]
- [[https://raw.githubusercontent.com/nicobailon/pi-subagents/main/docs/extension-api.md][current extension API]]
- [[https://raw.githubusercontent.com/nicobailon/pi-subagents/main/src/extension/rpc.ts][current RPC implementation]]

Public methods remain:

#+begin_example
ping status spawn steer interrupt stop resume
#+end_example

The process-local event-bus RPC is real and sufficient for an in-process adapter
to spawn and control a run whose package ID it already knows. It does not expose
mission operations. Its bounded fleet projection uses reconciliation keys rather
than actionable IDs.

The current =stop= RPC path directly resolves an async run and calls the stop
control channel instead of the normal executor path used by =steer=, =interrupt=,
and =resume=. It validates current-session ownership and running state, but does
not invoke the normal =authorityPolicy= gate.

Verdict:

- *adapter-owned exact control is technically possible*;
- *full discovery of every actionable current run is not yet a public structured
  contract*;
- *authority-safe stop remains a blocker before advertising stop*;
- *mission-first Stage 3 remains blocked on a public mission API*.

* Minimal Upstream Surface
:PROPERTIES:
:ID: pi-workbench-upstream-minimum
:TYPE: proposal
:END:

** Pi core

The minimum addition is not “Workbench support.” It is one generic namespaced
structured extension RPC handler:

#+begin_example
pi.registerRpcMethod("workbench.v1", async (payload, ctx) => structuredReply)
#+end_example

Minimum semantics:

- bounded structured input/output;
- provenance and namespace ownership;
- structured extension errors;
- existing outer Pi RPC =id= correlation;
- teardown/reload invalidation.

Workbench negotiates its schema inside the payload. Custom pushed events, host
cancellation, and advanced backpressure are follow-up production capabilities,
not prerequisites for the first correct snapshot-and-steer request/reply seam.
Snapshots remain authoritative while =deltas: null=.

This small facility would also serve other IDE/integration packages without
abusing slash commands or extension UI.

** pi-subagents

Stage the public asks instead of blocking the first steer slice on all of them:

1. *Adapter-owned steer now*: existing =spawn=/=steer= RPC already returns exact
   adapter-owned run identity and acknowledged delivery; it needs only the Pi
   bridge.
2. *Arbitrary-run discovery*: add a structured =snapshot= with package run ID,
   stable child index, owning session, lifecycle/activity state, permitted
   controls, and artifact links.
3. *Stop*: route RPC stop through normal authority policy and link accepted stop
   to terminal lifecycle/process proof.
4. *Mission workflows*: expose
   =mission.list/show/create/update/attach-run/resolve-decision/close= over the
   event bus.
5. *Optional hardening*: mint opaque action handles if raw IDs should remain
   package-private.

A snapshot may initially declare =coverage: adapter-owned-only= rather than
pretend completeness.

** Pimacs

Promote or wrap a deliberately small client API:

- send correlated asynchronous RPC command;
- subscribe/unsubscribe by event type;
- identify owner connection/session/project;
- observe process replacement and liveness;
- visit owning chat;
- reject pending callbacks during cleanup.

Workbench should contain private compatibility in one file until this API lands.

* Stage 0 Without Waiting for Upstream
:PROPERTIES:
:ID: pi-workbench-spike
:TYPE: plan
:END:

A model-free proof can be built today without pretending it is final transport:

1. register a global =/workbench-rpc= extension command;
2. Pimacs sends it through ordinary RPC =prompt= with an encoded inner request;
3. the extension validates the envelope and calls process-local =pi-subagents=
   RPC;
4. the extension writes a structured custom session entry with =pi.appendEntry=;
5. Pimacs retrieves it through =get_entries(since: cursor)=;
6. process replacement rotates owner epoch and invalidates handles.

This proves:

- exact adapter-owned target routing;
- request/reply correlation;
- malformed request handling;
- owner epoch rotation;
- control receipt rendering;
- read-model and section UX.

It does not prove:

- push events;
- acceptable latency under polling;
- full actionable run discovery;
- authority-safe stop;
- mission control;
- final transport ergonomics.

Do not encode status in =setWidget=, notifications, terminal text, or LLM-visible
messages. Custom entries are chosen because they are structured, durable,
non-model context and cursor-readable. Delete this bridge once generic extension
RPC exists.

* Vertical Slice to Build First
:PROPERTIES:
:ID: pi-workbench-first-slice
:TYPE: plan
:END:

The research strengthens the original narrow slice:

#+begin_quote
operational attention → exact source/attempt → evidence → targeted steer
→ control receipt → return to attention
#+end_quote

Limit v0 to:

- one Pimacs owner;
- adapter-owned attempts;
- read-only stale history for everything else;
- three attention buckets: explicit request, blocking failure, advisory stale;
- visits to child transcript/output/artifact;
- steer only as the first mutation;
- no stop until authority is fixed;
- no mission editing until mission RPC exists.

Why steer first:

- current =pi-subagents= already provides acknowledged steering;
- it exercises exact identity, frozen anchors, request correlation, receipts, and
  reconciliation;
- it is less destructive than stop/retry;
- it directly tests the user’s desired “quickly target that agent from the last
  context point” experience.

* Research-Driven Amendments to the Main Spec
:PROPERTIES:
:ID: pi-workbench-amendments
:TYPE: review
:END:

The next revision of =PI-WORKBENCH.org= should add:

1. *Attention ownership*: Gerrit-like expected actor/role and leave/re-enter rules.
2. *Receipt timing*: =createdAt=, =acceptedAt=, =completedAt=, and late outcome
   transition after =outcome_unknown=.
3. *Redaction/retention*: commands, prompts, outputs, and receipts may contain
   secrets; every durable field needs bounds and user-clear semantics.
4. *Transient safety*: never persist/replay owner epoch, handle, revision, or
   sensitive intervention content in Transient history.
5. *Transport torture tests*: split UTF-8, split/multiple JSONL frames,
   filter/sentinel interleaving, dead buffers, late callbacks, bounded undecoded
   remainder.
6. *Refresh fallback*: define behavior under deletion, reparenting, sorting, and
   filtering; identity lineage ordering must be explicit.
7. *Replay safety*: checkpoint/resume may re-execute pre-interrupt work; expose
   idempotency risk.
8. *Attempt authority*: mark attempts =current=, =parallel=, =superseded=, or
   =abandoned= so history does not imply all attempts are live control targets.

* Final Recommendation
:PROPERTIES:
:ID: pi-workbench-feasibility-recommendation
:TYPE: decision
:END:

Proceed with Workbench-native supervision.

- Build the OTP-style supervisor kernel before the complete status buffer.
- Spawn one real named Pi RPC child with a bounded context capsule.
- Prove exact-target steer, monitor/sentinel exit, control receipt, and parent
  handoff using standard Pi RPC.
- Treat =pi-subagents= seams as later compatibility work, not launch blockers.
- Do not auto-restart agent attempts; replacement always creates linked identity.
- Treat Magit as interaction grammar, Gerrit as attention grammar, Temporal as
  message/receipt grammar, Kubernetes as identity/reconciliation grammar,
  LangGraph as interrupt grammar, Elixir/OTP as supervision grammar, and Claude
  teams as a usability prior only.

This combination is novel enough to matter: no surveyed system combines
Emacs-quality semantic text interaction, durable authored intent, exact agent
control, an operator attention inbox, and acknowledged intervention receipts.
The opportunity is real precisely because the existing precedents each solve
only one plane well.
