This is the canonical Magpi document. It composts the useful parts of
=PI-WORKBENCH.org= and =PI-WORKBENCH-FEASIBILITY.org=. Those files remain source
notes; contradictions resolve in favor of this file.

Plane separation for authored why, attempt lineage, and git/worktree
isolation is normative in [[file:INTENTION-WORKSPACE.org][INTENTION-WORKSPACE.org]]. Build order still
resolves here; that file wins only on the intention/workspace split.

The build order is normative. A later phase may not smuggle an unproven concern
into an earlier one.

* Thesis
:PROPERTIES:
:ID: magpi-thesis
:TYPE: vision
:END:

Magpi is an actionable Emacs porcelain over a durable Elixir supervisor for Pi
sessions.

#+begin_quote
Emacs owns embodied intention. Elixir owns runtime supervision. Pi performs the
work. Every intervention names an exact attempt and produces evidence.
#+end_quote

The user should answer, at a glance:

1. What did I intend?
2. What is happening?
3. What needs me?
4. Where is the evidence?
5. What exact series of action stairstepped can express  my intention?

* Governing Decisions
:PROPERTIES:
:ID: magpi-decisions
:TYPE: decision
:END:

1. *Workbench-owned*: Magpi, not =pi-subagents=, owns deliberate Pi attempts.
2. *Elixir core*: OTP owns processes, lifecycle, policy, journal, and recovery.
3. *Emacs frontend*: point, markers, buffers, Magit sections, Transients, and
   context drafting remain in Emacs.
4. *Pi unchanged*: attempts use ordinary =pi --mode rpc=.
5. *Explicit context*: bounded capsules replace ambient transcript inheritance.
6. *Immutable attempts*: retry, resume, fork, and replacement never rewrite
   history.
7. *No automatic agent restart*: infrastructure may restart; attempts do not.
8. *Attention first*: attention is an operator projection, not lifecycle state.
9. *Read before write*: inspection ships before intervention.
10. *One owner*: one GenServer is the sole writer for one attempt state.

* Nouns
:PROPERTIES:
:ID: magpi-nouns
:TYPE: reference
:END:

| Noun       | Exact meaning |
|------------+---------------|
| Intention  | Authored objective; optional grouping record when membership exists |
| Mission    | Later enrichment of Intention (decisions, evidence, close). Not a parallel type |
| Attempt    | One immutable Pi execution incarnation |
| Child      | Attempt whose provenance names a parent attempt |
| Generation | OS-process incarnation used during startup/recovery |
| Capsule    | Frozen, bounded context passed at launch |
| Workspace  | Filesystem locus and writer grant for an attempt |
| Event      | Append-only observed fact |
| Snapshot   | Materialized state at a journal revision |
| Attention  | Derived request for human action |
| Anchor     | Frozen human or evidence location |
| Control    | Exact-target operator request |
| Receipt    | Request, delivery, operation, and proof record |
| Evidence   | Artifact supporting a claim or acceptance condition |

A supervision tree contains failure ownership. A mission graph contains intent.
An attention list contains requested human action. A workspace/git graph contains
mutation containment. They are not one tree. See
[[file:INTENTION-WORKSPACE.org][INTENTION-WORKSPACE.org]].

* Pattern Order
:PROPERTIES:
:ID: magpi-pattern-order
:TYPE: architecture
:END:

The order is deliberate.

** 1. Identity before process

Mint =attempt_id= before OS spawn. Record launch intent before observing output.
Display names never control anything.

Identity:

#+begin_example
{attempt_id, generation, parent_attempt_id?, intention_id?}
#+end_example

** 2. Ownership before concurrency

One =Magpi.Attempt= GenServer owns one attempt state and one Pi subprocess.
No process filter, UI callback, or projector may mutate it directly.

** 3. Mailbox before projection

All external facts become messages. The Attempt reduces one ordered mailbox.
The UI consumes snapshots; it never races raw events.

** 4. Supervision before recovery

Define child specs, restart policy, shutdown, and failure isolation before
persisting attempts. Recovery without explicit lifecycle semantics merely
resurrects ambiguity.

** 5. Journal before intervention

Record a control request before dispatch. Record acknowledgement and outcome
separately. If Magpi cannot explain what happened, it may not mutate.

** 6. Reconciliation before liveness claims

Streaming events make the view timely. RPC snapshots make it trustworthy. Gaps
produce stale/read-only state, never guessed state.

** 7. Projection before action

First prove stable read-only sections, point, folding, and visits. Only then bind
mutating suffixes.

** 8. Steer before terminate

Steer exercises identity and receipts with limited blast radius. Termination adds
process proof. Replacement adds saga semantics.

** 9. Attention before automation

Derive a quiet, deterministic human queue before adding autonomous policy. Never
auto-act on a noisy signal.

** 10. One project before federation

One owner, one project, one writer path. Multi-project views and foreign backends
come last.

:PROPERTIES:

:TYPE: architecture
:END:

#+begin_example

├─ Magpi.Registry                       :permanent
├─ Magpi.Journal                        :permanent

** Supervisor policy

| Child | Restart | Reason |
|-------+---------+--------|
| Registry | permanent | Infrastructure identity |
| Journal | permanent | Durable single writer |
| Attention projector | transient | Reconstructible derivative |
| Gateway | transient | Client transport |
| Pi attempt | temporary | Re-execution may duplicate effects |

Default strategy is =:one_for_one=. Child failure does not kill siblings, parent,
or descendants. Cascades are explicit controls, never links hidden in topology.

Restart intensity and exponential backoff apply only to infrastructure. Repeated
infrastructure failure closes admission and opens attention; it does not churn Pi
attempts.

** Attempt process

=Magpi.Attempt= is a GenServer and subprocess owner.

Responsibilities:

- validate and hold the immutable child spec;
- start one Pi RPC subprocess;
- frame and decode JSONL;
- serialize events and controls;
- expose a materialized snapshot;
- monitor process exit;
- write lifecycle facts through the Journal;
- produce parent handoff and terminal evidence.

Long-lived attempts are not Tasks. =Task.Supervisor= is reserved for bounded
validation or artifact work.

** Monitor semantics

The external process is monitored, not semantically linked to family members.
Its exit is a fact:

#+begin_example
{:process_exit, attempt_id, generation, exit_status}
#+end_example

Exit does not imply rollback, mission failure, or safe replacement. Filesystem
state is reconciled before another writer begins.

** Let it crash

Let corrupt infrastructure fail, preserve the fact, and rebuild reconstructible
state. Never translate “let it crash” into “rerun the model.”

* Domain State Machines
:PROPERTIES:
:ID: magpi-state-machines
:TYPE: behaviour
:END:

** Attempt

#+begin_example
declared → starting → running → settling → terminal
                  ↘ failed ───────────────↗
#+end_example

Terminal outcome is one of:

| Outcome | Meaning |
|---------+---------|
| completed | Pi settled normally |
| failed | Provider, protocol, or startup failure |
| terminated | Operator completed termination |
| lost | Ownership/process truth cannot be established |

=lost= is read-only until reconciliation. Recovery creates a new attempt, never a
new meaning for the old ID.

** Control

#+begin_example
created → accepted | rejected
accepted → dispatched → succeeded | partial | failed | outcome_unknown
#+end_example

Delivery, operation completion, process exit, and mission success remain distinct
facts.

** Attention

#+begin_example
open → acknowledged-until-change | snoozed → open | resolved
#+end_example

Priority:

1. explicit human request;
2. blocking failure or conflict;
3. stale/advisory observation.

Attention deduplicates by source identity and reason. “Paused,” “old,” or “not
green” is not sufficient.

* Context Capsules
:PROPERTIES:
:ID: magpi-context
:TYPE: protocol
:END:

Emacs drafts context because it owns point and buffers. Dispatch freezes it:

#+begin_example
ContextCapsule {
  id
  objective
  selected_parent_entries[]
  decisions[]
  anchors[]
  file_excerpts[]
  constraints[]
  non_goals[]
  role_instructions
  expected_output
  acceptance
  provenance: {parent_session_id, parent_entry_id, captured_at}
}
#+end_example

Rules:

- Full transcript inheritance is opt-in.
- Each excerpt records path, range, digest, and capture time.
- Live markers remain Emacs-local; durable fallback is file/range/digest.
- Capsules are size-bounded and inspectable before launch.
- Missing context is reported; it is not silently replaced by broad inheritance.

* Journal and Recovery
:PROPERTIES:
:ID: magpi-journal
:TYPE: architecture
:END:

The Journal is a single writer of bounded append-only facts. It is not a dump of
transcripts.

Persist:

- attempt declaration and lineage;
- process generation and terminal fact;
- control request and receipt transitions;
- mission/acceptance decisions;
- attention transitions;
- artifact references and digests;
- parent handoffs.

Do not persist:

- live Emacs markers;
- replayable capability handles;
- full provider streams;
- secrets;
- large artifacts already owned elsewhere.

On restart, replay produces a read-only snapshot. Live ownership must be proven
before controls re-enable.

Journal health is an admission gate. If durable append fails, new launches and
controls reject; existing attempts continue under monitoring and become stale
until reconciliation. Magpi never performs an external mutation it cannot first
record.

Initial storage is project-scoped JSONL plus periodic compact snapshot. A database
is not justified until query or contention proves the need.

* Emacs Frontend
:PROPERTIES:
:ID: magpi-emacs
:TYPE: architecture
:END:

Emacs is a first-class frontend, not a dumb shim.

Responsibilities:

- start/connect to Magpi core;
- draft and preview capsules;
- preserve live anchors;
- render Attention, Mission, Attempts, and History;
- resolve semantic target at point;
- construct contextual Transients;
- show receipts and stale state;
- visit transcripts, files, patches, and artifacts.

Pimacs contributes chat rendering, Markdown, diffs, session affordances, and Pi
semantics. Magpi must isolate Pimacs private calls behind one compatibility
module. Long term, Pimacs should accept a transport abstraction so Magpi can
proxy an Elixir-owned Pi session into a Pimacs chat buffer.

Magpi's =magpi-status.el= composes =magit-mode='s transactional refresh (stable
point, folding, and window position) with Magit Section's typed sections.
Transient supplies intent previews. Rendered text is never parsed to recover
identity.

* Lean Cut — Walking Skeleton
:PROPERTIES:
:ID: magpi-lean-cut
:TYPE: plan
:END:

Before committing the full supervisor, realize the interaction once using the
existing Pimacs multi-session backend. This is a bounded experiential probe, not
the production runtime.

** User journey

#+begin_example
state intention
  → choose a thinking-depth profile
  → spawn named agent
  → enter its first-message chat buffer
  → observe activity and changed-file links
  → visit a changed file
  → spawn a second agent
  → return to Magpi status
  → TAB each attempt to peek intent, activity, files, and last response
#+end_example

An authored intention is always the attempt heading. If it is absent, the
heading is a quiet =◯=. A title is a display observation only: it never fills
or mutates authored intent and never becomes the heading. Activity never
replaces an authored intention.

** Status shape

#+begin_example
MAGPI · project

▼ Refactor token refresh                    running · Standard · anthropic/claude-sonnet
    intent     Make refresh handling explicit and tested
    model      anthropic/claude-sonnet
    usage      ↑50.0k ↓10.0k R40.0k · ctx 60.0k/200.0k · $0.45
    activity   edit lib/auth/token.ex
    files      lib/auth/token.ex
    last       Added refresh validation; running focused tests…

▶ Review telemetry simplification              idle · Deep · openai/gpt-4.1
#+end_example

=TAB= reveals; =RET= visits the attempt chat or file at point; =s= spawns; =g=
refreshes; one global command returns to this buffer.

** Launch transient

Primary choices:

| Choice | Default | Meaning |
|--------+---------+---------|
| Intention | optional | Immutable authored heading; =◯= when absent. Title is never heading identity |
| Model | Inherit | Canonical =provider/model= id, or Inherit (=requested-model= nil) |
| Effort | Profile | Thinking depth; Profile defers to the named profile |
| Profile | Standard | Named effort preset (Default/Quick/Standard/Deep and Off..Max) |
| Context | Point | None, point, region, selected files |
| Authority | Writer | Read-only or writer |

Dispatch freezes thinking from Effort (or Profile when Effort is Profile), plus
semantic authority and context. Requested and running model values share the same
opaque canonical identifier; only the adapter decodes provider/model transport
arguments. Status applies a face hierarchy so identity, activity, authority, and
evidence scan at different weights. Launch atomically installs the listener
and may emit initial state observations. `send-initial' is a separate backend
operation, invoked only after that listener is ready; it compiles and sends the
initial prompt at most once. Model enumeration is asynchronous and session-scoped
on an explicit handle; any change records a running-model observation. Status
refresh paints the registry; it does not pull snapshots. `g` (and one open-time
call) reconcile transport-only facts. Restated facts keep the same attempt object
and do not schedule another paint. Point/Region context is source-file evidence;
Magpi and Pimacs buffers default to None so porcelain cannot re-enter the prompt.

The Lean Cut domain has three plain records only:

#+begin_example
Attempt(id, intent, launch, observation, started-at)
Launch(root, profile, requested-model, thinking, authority, context)
Observation(display-title, activity-state, connection-state, running-model,
            observed-files, last-response, problem, usage)
#+end_example

The reducer is a plain function: =attempt-reduce(attempt, event) -> new-attempt=.
The registry replaces the value by attempt ID; backend listeners do not retain a
mutable attempt object.

** Lean backend

Use Pimacs’s existing named chats and standard Pi RPC events. The implemented
=magpi-backend.el= contract is the only runtime surface used by =magpi.el=;
=magpi-pimacs-backend.el= is the sole consumer of Pimacs private APIs.

#+begin_example
spawn(attempt, listener) send-initial(handle, attempt) visit(handle)
send(handle, message, mode)
terminate(handle)
#+end_example

The first backend is ephemeral and Emacs-owned. The later Elixir backend
implements the same semantic contract. UI code may not reach through the boundary
into Pimacs hash tables.

Pimacs session names are adapter transport identities. They include the complete
attempt ID (with a concise intent prefix) so attempts at the same root cannot
collide through presentation truncation.

** Changed-file evidence

For the cut, show only files observed in structured =edit= or =write= tool calls.
Label them =observed files=; do not claim a complete worktree diff. =RET= opens
the exact path. Git reconciliation belongs after the journey proves useful.

** What survives the probe

Keep:

- immutable attempt ID and authored intention or explicit absence;
- launch specification and profile resolution;
- backend protocol;
- status sections and navigation grammar;
- event reduction tests;
- context anchors.

Expect to replace:

- ephemeral process registry;
- Pimacs-private process ownership;
- in-memory lifecycle history.

** Lean gate

The cut passes when one user can, without reading documentation:

1. state an intention and choose a thinking-depth profile;
2. land in the child’s first-message buffer;
3. return to status and still see the original intention;
4. jump to an observed changed file;
5. spawn a second independent agent;
6. fold/peek both attempts without confusing their state or target.

No mission editor, daemon, journal, worktree manager, automatic attention, or
foreign backend enters this cut. If this journey is not compelling, stop before
building the supervisor.

* Build Phases
:PROPERTIES:
:ID: magpi-phases
:TYPE: plan
:END:

The next phase begins only after its predecessor’s gate passes.

** Phase 0 — Contract and fake
:PROPERTIES:
:ID: magpi-phase-0
:END:

Goal: make semantics executable without Pi, providers, or Emacs.

Build:

- nouns and structs;
- attempt/control state machines;
- protocol codec;
- deterministic fake Pi executable;
- invariant tests.

Gate:

- invalid transitions reject;
- IDs are minted before spawn;
- duplicate request/event IDs are idempotent;
- fixtures are deterministic and credential-free.

Do not build: UI, mission editing, worktrees, real provider calls.

** Phase 1 — Supervision kernel
:PROPERTIES:
:ID: magpi-phase-1
:END:

Goal: prove OTP ownership and failure containment.

Build:

- Application/Supervisor;
- Registry;
- DynamicSupervisor;
- temporary Attempt worker;
- fake subprocess ownership;
- monitor/exit handling;
- restart intensity for infrastructure.

Gate:

- attempt crash does not restart or affect siblings;
- infrastructure follows declared restart policy;
- no callback writes another process’s state;
- graceful and abnormal exit become deterministic facts.

Do not build: persistence or real Pi.

** Phase 2 — Journal and reconstruction
:PROPERTIES:
:ID: magpi-phase-2
:END:

Goal: explain every lifecycle transition and rebuild state.

Build:

- append-only journal;
- materialized snapshot;
- control receipt transitions;
- replay/reconstruction;
- redaction and bounds.

Gate:

- kill/restart core and reconstruct the same terminal snapshot;
- pending controls become =outcome_unknown=;
- replay never enables control without live ownership proof.

Do not build: broad querying or database storage.

** Phase 3 — Emacs gateway
:PROPERTIES:
:ID: magpi-phase-3
:END:

Goal: prove a thin, strict Emacs ↔ Elixir connection.

Build:

- stdio JSONL gateway;
- =magpi-connection.el=;
- hello/version/snapshot/spawn/shutdown;
- bounded request correlation;
- reconnect-to-snapshot within one core lifetime.

Gate:

- split UTF-8 and multiple frames decode correctly;
- dead buffers and late replies are harmless;
- malformed input cannot mutate state;
- Emacs displays a fake-attempt snapshot.

Do not build: Magit UI or mutations.

** Phase 4 — One real Pi attempt
:PROPERTIES:
:ID: magpi-phase-4
:END:

Goal: supervise one real =pi --mode rpc= process.

Build:

- Pi command builder;
- subprocess spike: bare Port versus a focused library;
- separate protocol stdout from stderr;
- context capsule launch;
- RPC prompt/state/events;
- terminal handoff.

Gate:

- launch from a bounded capsule;
- observe streaming/tool/settled events;
- terminate and observe process proof;
- no provider text is parsed as control state;
- failed startup leaves an attributable attempt.

Do not build: more than one writer.

** Phase 5 — Read-only porcelain
:PROPERTIES:
:ID: magpi-phase-5
:END:

Goal: make state tractable before making it mutable.

Build:

- Attention, Attempts, and History sections;
- stable point, folding, window start;
- transcript/file/artifact visits;
- stale and disconnected rendering;
- projection switch/back.

Gate:

- refresh preserves semantic location;
- deletion/reordering has deterministic fallback;
- =RET= only inspects;
- no command parses rendered text.

Do not build: lifecycle mutation.

** Phase 6 — Exact intervention
:PROPERTIES:
:ID: magpi-phase-6
:END:

Goal: prove contextual control against one owned attempt.

Build in this order:

1. steer;
2. follow-up;
3. interrupt current turn;
4. graceful terminate;
5. forced termination after timeout;
6. replacement as a linked attempt.

Gate:

- every control checks attempt/generation/revision;
- every control has a receipt;
- delivery, operation, and process proof remain distinct;
- stale targets reject rather than retarget.

Do not build: autonomous retry.

** Phase 7 — Attention
:PROPERTIES:
:ID: magpi-phase-7
:END:

Goal: create a quiet operator inbox from trusted facts.

Build:

- explicit, blocking, advisory buckets;
- source-bound deduplication;
- expected actor/role;
- acknowledge-until-change;
- snooze;
- typed request/response schema.

Gate:

- routine active work does not alert;
- acknowledgement expires only on source change;
- every item visits its source;
- attention never mutates lifecycle.

Do not build: automatic response.

** Phase 8 — Mission and acceptance
:PROPERTIES:
:ID: magpi-phase-8
:END:

Goal: join authored intent to attempts and evidence.

Build:

- mission/intention records as collapsible status headers;
- acceptance requirements;
- decisions and next action;
- attempt attachment/lineage (membership and provenance, not git forks);
- verification evidence;
- close intent semantics (refuse new attaches);
- workspace remains the project root unless Phase 9 exists.

Gate:

- author → launch → attend → inspect evidence → decide → close;
- absent intent remains absent;
- process completion never auto-closes a mission;
- intention headers group attempts without creating worktrees.

Normative detail: [[file:INTENTION-WORKSPACE.org][INTENTION-WORKSPACE.org]].

** Phase 9 — Worktrees and one-writer policy
:PROPERTIES:
:ID: magpi-phase-9
:END:

Goal: make mutation containment explicit as a workspace plane, not as mission
identity.

Build:

- workspace refs on attempts;
- policies: =shared-root=, =worktree-per-writer=, =inherit-parent=, =explicit=;
- managed worktree lifecycle;
- one writer per workspace;
- dirty-state preservation;
- replacement preflight and explicit workspace handoff;
- cleanup receipts;
- concurrency and budget policy.

Gate:

- conflicting writers reject before launch;
- failed cleanup preserves recovery paths;
- replacement cannot begin before prior writer terminal proof;
- workspace fork and attempt fork remain distinct operations;
- branch/worktree labels never become intention identity.

Normative detail: [[file:INTENTION-WORKSPACE.org][INTENTION-WORKSPACE.org]].

** Phase 10 — Durable daemon and federation
:PROPERTIES:
:ID: magpi-phase-10
:END:

Goal: outlive one Emacs connection, then scale ownership.

Build in order:

1. daemon lifecycle independent of Emacs;
2. authenticated local reconnect;
3. one reconnecting Emacs client;
4. multiple projects;
5. optional additional clients;
6. read-only foreign backend adapters.

Gate:

- UI disconnect does not kill attempts;
- reconnect obtains a coherent snapshot;
- owner routing is unambiguous;
- foreign runs cannot claim unsupported controls.

|------------+-------------------+-----------------|

* V1 Definition
:PROPERTIES:
:ID: magpi-v1
:TYPE: acceptance
:END:

V1 is complete when one user can:

1. open Magpi in one project;
2. freeze point/region into a capsule;
3. launch one supervised Pi attempt;
4. inspect live activity and evidence;
5. steer the exact attempt;
6. see an acknowledged receipt;
7. interrupt or terminate it safely;
8. observe terminal proof;
9. return to the dispatch anchor;
10. restart the UI and recover a truthful read-only history.

V1 does not require missions, worktrees, federation, or =pi-subagents= control.
Those are valuable only after the base is firm.
