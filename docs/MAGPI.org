* Authority

This file is the canonical Magpi design. Git holds prior proposals and notes.
When they disagree, this file wins.

* Proposition

Magpi is a small Emacs porcelain for deliberate Pi work in one Git repository.

#+begin_quote
State the why. Bind only the context it needs. Spawn an action. See the work. React.
#+end_quote

#+begin_example
intention → action → chat / edits → glance changes → Magit → react
#+end_example

It should make that loop quieter and safer than coordinating chats, worktrees,
and Magit by hand. It is not an agent OS, workflow engine, second chat client,
fleet dashboard, or shadow Git.

* Names

| Name | Being | Not |
|------+-------+-----|
| Intention | the why | a prompt, a branch, a chat |
| Action | one doing | a ticket, a retry of the same |
| Changes | the flux (values on the intention) | a struct, a workspace |
| Role | =writer= or =reader= | authority, access |
| Bind | give context to the surface at point | a hidden prompt |
| React | intervene in the world | chat prose, automatic approval |
| Observation | reported fact | permission |
| Ask | Pi question inside an observation | a Magpi aggregate |
| Adapter | Pimacs translation | a runtime, a plugin platform |

Glance is colour and mark. Depth is Magit. Chat is Pimacs. Git is Git.

* Essential model

Only distinctions which change ownership or user action deserve representation.

#+begin_example
Intention(id, objective, bindings[], change?, state, action_ids, writer_lease?, audit)
Change(source_root, worktree_path, branch, base_ref)   ; values, not a record
Action(id, intention_id?, prompt, launch, observation, chat_ref?, started_at)
Launch(root, requested_model?, thinking, role, context)
Observation(title?, activity?, connection?, running_model?, files?, last?, problem?, asks[])
Ask(id, question, state, paths?, parent_id?)           ; inside observation
#+end_example

An intention is one authored objective. Bindings are context, never silently a
prompt. It gains one managed Git change only when its first action starts. An
action is one execution and never inherits the objective as its prompt. Retry is
another id. A standalone action may run in the current checkout without an
intention.

Do not extract a Workspace. While one intention has one worktree, Change stays
fields on the intention.

* Invariants

1. *One intention, one change once work starts.*
2. *Objective is not a prompt.* Only the action prompt and explicitly bound
   context enter chat.
3. *Action identity precedes spawn.* Retry creates another id.
4. *One writer.* The writer role takes the lease before spawn. Readers do not.
5. *Uncertainty stays visible.* Disconnect cannot release a lease or claim
   completion. Writer release is operator recovery, not a fence.
6. *Git tells Git facts.* Missing is missing, not clean or zero.
7. *Observation is not permission.* Titles, activity, paths, and rendered text
   never become identity or intent.
8. *Read before write.* Navigation never mutates. React is explicit and confirmed.
9. *Action exit does not decide the why.* Only the user merges or discards.
10. *One owner for now.* One controlling Emacs. The repository file is not a
    distributed lock.

* Ownership

| Concern | Owner |
|---------+-------|
| Why, bindings, change, lease, Git mutations | Magpi Lisp |
| Point, buffers, sections, Transients | Emacs |
| Diff, stage, commit, history | Git and Magit |
| Chat, Pi protocol, session rendering | Pimacs and Pi |
| Durable process supervision | Deferred |

One adapter, =magpi-pimacs-backend.el=, holds Pimacs-private knowledge. Magpi sees:

#+begin_example
spawn(action, listener)
send_initial(handle, action)
visit(handle)
send(handle, message, mode)
terminate(handle)
reconcile(handle, listener)
respond_ask(handle, ask_id, response)   ; when the adapter can
#+end_example

A seam around present dependency, not a backend platform.

* Interaction

Status is an intention dashboard, not a process inventory. The heading is why
plus a Git glance. Nested rows are actions and their observations. A pending
reaction is a mark, not a lecture.

| Key | Meaning |
|-----+---------|
| =i= | Create an intention |
| =@= | Bind context to the surface at point |
| =C-c m i= / =C-c m @= | Create or bind outside status |
| =s= | Spawn an action; keep the intention at point |
| =RET= | Intention → Magit; action → chat; ask → React |
| =TAB= | Fold |
| =g= | Reconcile observations and repaint |
| =m= / =d= / =l= / =c= | Magit status, diff, log, commit of the changes |
| =a= | React |
| =q= | Quit |

=s= is spawn in Magpi status and stage in Magit. Distinct modes, not a collision.

Launch defaults to =w= (writer). Press =w= to toggle =r= (reader).

- On an intention, =s= starts an action in its worktree.
- Elsewhere, =s= starts a standalone action in the current checkout.
- Creating an intention only persists why and bindings; the first action
  creates the worktree.
- Point may default; it never silently changes ownership.

Bind is contextual. Intention holds durable why-references. Action may hold this
doing's evidence. Launch may freeze point or region into the spawn. Porcelain
buffers are not source.

React is the intervention surface:

- Pi-ask → approve / reject
- Intention with writer → release (honest recovery)
- Intention quiescent → merge / discard
- Action disconnected → show uncertainty; do not fake completion

* Persistence

Beside Git metadata, persist only what must survive a buffer:

- intention id, objective, bindings, change identity, state, action membership
- writer lease
- stable chat references when the adapter can supply them
- a narrow audit of worktree, lease, merge, discard, and cleanup (object ids
  when Git mutations complete)

Git owns history. Pimacs owns chat. Files own contents. No transcript store,
database, journal, or daemon in anticipation.

States: =active=, =merged=, =discarded=. Richer states only with a user
operation that needs them.

* Build order

Each step must improve the loop on its own.

** 1. Close one intention loop

Create, bind, spawn, edit in the worktree, return, inspect through Magit, React
(release, then merge or discard).

Gate: the journey works without evaluating Lisp.

** 2. Make return effortless

Preserve point and folding. Visit chats and observed files. Distinguish observed
files from the Git diff. Persist enough to reopen prior action chats.

Gate: the user can always return from doing or evidence to its intention.

** 3. Make uncertainty honest

Partial spawn, stale observation, missing worktree, writer recovery, failed
merge or discard — no invented success.

Gate: interruption cannot silently free ownership.

** 4. Observe real use

Wrong-target actions, time to Git evidence, manual reconstruction, stale
leases, work lost on Emacs exit. Remove friction before adding architecture.

** 5. Decide whether a runtime is earned

Only if Emacs/Pimacs fails the loop: survive Emacs exit; process ownership
Pimacs cannot provide; multiple clients; recovery beyond the audit; recurrent
harm.

First prove one external owner, one reconnect, one rejected stale control. If
that proof removes no observed limitation, do not integrate. If earned, it owns
only runtime facts — not markers, Magit, intention, or chat.

* Deliberately absent

Until evidence demands them: Elixir/OTP daemon; event sourcing; attention
inbox; workflow graph; retries and automatic approval; multiple worktrees per
intention; fleet and federation; generic backend platform; Org as runtime state.

* Immediate next step

Finish the ordinary path: attributable writer release, then guarded merge or
discard, through React. Then use Magpi for real work. No runtime is more
valuable than learning whether this small loop enlarges intention and preserves
flow.
