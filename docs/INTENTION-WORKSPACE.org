* Authority
:PROPERTIES:
:ID: magpi-intention-workspace-authority
:TYPE: decision
:END:

This document freezes one architectural understanding:

#+begin_quote
Intentions group attempts. Workspaces isolate writers. They are not the same
tree.
#+end_quote

Contradictions with exploratory notes resolve in favor of [[file:MAGPI.org][MAGPI.org]] for build
order, and in favor of this file for the why / run / locus split.
Implementation may lag the model; the model must not collapse the questions to
match an early UI shortcut.

* Decision
:PROPERTIES:
:ID: magpi-intention-workspace-decision
:TYPE: decision
:END:

** Accepted

1. An *intention* is a durable authored objective. Grouping records come later;
   until then the text lives on the attempt as a launch freeze.
2. An *attempt* is one immutable Pi execution incarnation. Retry, resume, fork,
   and replacement mint a new attempt with provenance; they never rewrite the
   parent.
3. A *workspace* is the mutable filesystem locus an attempt may write. It is
   chosen at launch, recorded on the attempt, and enforced by one-writer rules.
4. Three questions, three edges:
   - intention membership answers “why does this work exist?”
   - attempt provenance answers “which execution graph is this?”
   - workspace grant answers “which files may this writer touch?”
5. Children inherit *intention membership* by default. They do *not* inherit a
   git fork, a writer lock, or ambient transcript.

** Rejected

1. Intention *is* a git branch, worktree, or Magit review vehicle.
2. Spawning under an intention creates a forked worktree.
3. Collapsing mission graph, attempt provenance, supervision, attention, and git
   topology into one meta-tree.
4. Inferring intention from branch name, worktree path, last file touch, or model
   summary.
5. Letting process completion auto-close an intention.
6. Storing a default workspace policy on an intention. Why must not own where.
7. An =Unassigned= bucket. Ungrouped attempts are top-level rows.

* Questions
:PROPERTIES:
:ID: magpi-intention-workspace-planes
:TYPE: architecture
:END:

Magpi answers three questions over one normalized model. They share identifiers
by reference; they do not share ownership semantics.

| Question | Authoritative fact | Not |
|----------+--------------------+-----|
| Why does this work exist? | Intention membership; authored objective | Branch, title, path, activity |
| Which execution is this? | Attempt id + optional provenance | Supervision tree, folder nest |
| Which files may this writer touch? | Workspace ref + grant | Intention identity, mission header |

Hard rule from [[file:MAGPI.org][MAGPI.org]]:

#+begin_quote
A supervision tree contains failure ownership. A mission graph contains intent.
An attention list contains requested human action. They are not one tree.
#+end_quote

This document adds: a git/worktree graph contains mutation containment. It is
also not that tree.

Attention is a derived inbox. Supervision is OTP. Provenance is an optional
edge on the new attempt. None of those is a fourth schema.

* Nouns
:PROPERTIES:
:ID: magpi-intention-workspace-nouns
:TYPE: reference
:END:

| Noun | Exact meaning |
|------+---------------|
| Intention | Authored objective. Optional grouping record when membership exists. |
| Attempt | One immutable Pi execution incarnation with frozen launch + capsule. |
| Intent text | Launch freeze of that objective on the attempt. Not a second identity. |
| Child attempt | Attempt whose provenance names a parent attempt and relation. |
| Relation | =spawned= \| =forked= \| =resumed= \| =replaced= |
| Capsule | Frozen bounded context passed at launch; what the model is told. |
| Acceptance | Human done-when on the intention. Not capsule instruction. |
| Workspace | Filesystem locus + write grant (=shared-root= or a managed worktree). |
| Writer lock | Exclusive mutation grant for one workspace at a time. |
| Observed files | Tool-observed paths; not a claim of complete git status. |

One noun until decisions, evidence, and close exist. *Mission* is a later
enrichment or rename, not a parallel type.

Absent intention remains absent. Observed backend titles never fill authored
intent and never become the heading.

Capsule is what the model is told. Intention is what the human will accept.
They must not share a field name.

* Status Projection
:PROPERTIES:
:ID: magpi-intention-workspace-status
:TYPE: ui
:END:

** Shape

Lean cut: a flat attempt list. Authored intent is the heading. Title, if any,
is a body row.

#+begin_example
MAGPI · project

▼ Refactor token refresh                    running · Standard · anthropic/claude-sonnet
    intent     Make refresh handling explicit and tested
    activity   edit lib/auth/token.ex
    files      lib/auth/token.ex
    last       Added refresh validation; running focused tests…

▶ ◯                                         idle · Deep · openai/gpt-4.1
    intent     ◯
#+end_example

Later grouping, when membership records exist, nests attempts under the
authored objective. Ungrouped attempts stay top-level. Magpi does not invent a
group to tidy the buffer.

** Interaction grammar

| Binding | Meaning |
|---------+---------|
| TAB | Fold/unfold presentation only |
| RET | Visit exact target at point — never mutates lifecycle |
| s | Spawn; later may attach to the intention at point |
| g | Reconcile snapshot facts |

Navigation keys never invoke mutating ops.

** Header rules

- If authored intent is present, it is the heading.
- Observed title, activity, model, and branch never overwrite that heading.
- If intent is absent, the heading is =◯=. Title remains a body observation.
- Folding is presentation only. Hidden attempts remain addressable and retain
  locks, receipts, and attention sources.

** Lean-cut compatibility

Until grouping records exist, intention text is stored on the attempt. That is
a missing table, not a domain merge:

- domain stores intention text as authored immutable data on the attempt;
- promoting those strings into intention records later must preserve attempt
  ids and not rewrite history;
- workspace remains the project root.

* Domain Model
:PROPERTIES:
:ID: magpi-intention-workspace-model
:TYPE: architecture
:END:

** Records

The lean cut has three records. Add nothing until a gate fails.

#+begin_example
Attempt(id, intent, launch, observation, started-at)
Launch(root, profile, requested-model, thinking, authority, context)
Observation(display-title, activity-state, connection-state, running-model,
            observed-files, last-response, problem, usage)
#+end_example

When grouping is actually needed:

#+begin_example
Intention {
  id
  objective              // authored text
  acceptance?            // human done-when; omit if absent
  closed_at?             // refuse new attaches when set
}

Attempt {
  ...existing...
  intention_id?          // optional membership
  provenance?            // { parent_attempt_id, relation, at }
}
#+end_example

When two writers can collide:

#+begin_example
Workspace {
  ref                    // "root" | worktree id
  path
  writer_attempt_id?     // one writer
}
#+end_example

Resolved =workspace_ref= is recorded on the attempt before spawn. Dirty and
branch are observations or git facts, not identity. =created_from= is optional
workspace lineage, not attempt provenance.

Do not add:

- =Intention.status= or =paused=. Close is =closed_at= or a refuse-attach bit.
- =Intention.root=. The store is project-scoped.
- =Intention.default_workspace_policy=. Locus is chosen at launch.
- =Launch.workspace_policy=. Name a ref, or omit and reuse parent/root.
- =Attempt.workspace= as a catalog copy. Writer truth lives on Workspace.

** Invariants

1. =Attempt.id= is minted before OS spawn and never reused.
2. =Attempt.intent= and =Attempt.launch= are immutable after create.
3. =Observation= may not alter intent, launch, provenance, or workspace path.
4. =intention_id= is membership, not process ownership.
5. =provenance.parent_attempt_id= is lineage, not workspace parent.
6. Writer authority requires a workspace grant; read-only attempts may share a
   workspace without a writer lock.
7. Two writer attempts must not hold the same workspace ref concurrently.
8. Closing an intention does not terminate attempts; it refuses new attaches.
9. Terminating attempts does not close an intention.
10. Git branch names are never primary keys.
11. Observed titles never become authored intent or heading identity.

* Workspace
:PROPERTIES:
:ID: magpi-intention-workspace-policy
:TYPE: architecture
:END:

Until isolation exists, every attempt uses the project root. Writers are
serialized or rejected by lock.

Launch then answers three facts:

1. Which path?
2. May this attempt write?
3. Is another writer already there?

If a child should share a locus, name the parent’s workspace ref. If omitted,
reuse the parent attempt’s ref when present, otherwise the project root. Do
not invent a fork. Do not encode that choice as =inherit-parent= on the
intention.

** What children inherit

| Inherited by default | Not inherited by default |
|----------------------+--------------------------|
| Intention membership | Git fork/worktree |
| Capsule only if explicitly composed | Ambient transcript |
| Parent as provenance when spawned from an attempt | Parent writer lock |

** Fork meanings (do not conflate)

| Phrase | Means |
|--------+-------|
| Fork attempt | New attempt id, relation =forked=, new capsule/launch freeze |
| Fork workspace | New worktree locus; no attempt by itself |
| Spawn under intention | Membership edge only; workspace per launch |
| Replace attempt | New attempt, relation =replaced=; prior marked superseded; workspace transfer is explicit preflight |

A UI may sequence two ops. The domain has no compound
=fork-attempt-into-worktree=.

* Operations
:PROPERTIES:
:ID: magpi-intention-workspace-ops
:TYPE: protocol
:END:

All mutating ops remain exact-target and receipt-bearing per MAGPI.org.

Until a gate fails:

| Op | Effect |
|----+--------|
| =attempt.spawn= | Mint attempt; optional membership; resolve locus; spawn |

When grouping exists:

| Op | Effect |
|----+--------|
| =intention.create= | Mint intention; no process |
| =intention.attach= | Membership only |
| =intention.close= | Refuse new attaches |

When isolation exists:

| Op | Effect |
|----+--------|
| =workspace.grant_writer= | Lock or deny |
| =workspace.release= | Receipt + dirty preservation |

=attempt.fork=, =resume=, and =replace= already live in MAGPI.org. Do not
redefine them here with workspace transfer notes.

* Anti-Patterns
:PROPERTIES:
:ID: magpi-intention-workspace-antipatterns
:TYPE: decision
:END:

1. Using branch name, model title, or activity as the intention heading.
2. Creating a worktree because the user folded, spawned under, or closed an
   intention.
3. Drawing attempt children as file-tree nodes under a worktree header and
   calling that the mission view.
4. Moving an attempt between intentions by rewriting historical membership
   without a journalled reassignment event.
5. Treating collapsed sections as inactive runtime state.
6. Auto-assigning ungrouped attempts by path similarity.
7. Cleanup of worktrees on intention close without terminal proof and receipts.
8. Promoting =display-title= into =intent= to tidy headings.
9. Showing a policy line on an intention header.
10. Treating Magit merge as intention completion.

* Phase Mapping
:PROPERTIES:
:ID: magpi-intention-workspace-phases
:TYPE: plan
:END:

| When | Allowed realization |
|------+---------------------|
| Lean cut | Intent text on the attempt; flat list; shared root; observed files |
| Phase 8 | Intention records; nested headers; attach; acceptance; still shared root |
| Phase 9 | Workspace refs, one-writer locks, fork/cleanup receipts |
| After | A *project* default may prefer isolated worktrees for writer spawns |

Build order remains normative: do not smuggle workspace management into Phase 8
headers, and do not smuggle grouping records into the lean cut.

* Acceptance Gates
:PROPERTIES:
:ID: magpi-intention-workspace-gates
:TYPE: acceptance
:END:

** Model gate (doc/tests, any phase)

1. An attempt can belong to an intention without a private worktree.
2. Two attempts can share an intention and differ in workspace ref.
3. Two writer attempts cannot hold the same workspace ref.
4. Attempt fork without workspace fork leaves the workspace ref unchanged.
5. Workspace fork without attempt spawn creates no execution row.
6. Absent intention stays absent under projection and recovery.
7. Observation events cannot mutate intention objective, launch, or workspace
   path.
8. Authored intent, when present, is the heading; observed title never is.

** Mission UI gate (Phase 8)

1. Status shows intention headers with nested attempts.
2. TAB folds presentation only.
3. RET visits; no lifecycle mutation.
4. Spawn from an intention header attaches membership and freezes objective
   text onto the attempt.
5. Process exit does not close the intention.

** Workspace gate (Phase 9)

1. Writer launch that isolates records workspace ref before spawn.
2. Conflicting writers deny before launch.
3. Replacement preflight proves prior writer terminal or successful handoff.
4. Failed cleanup preserves recovery paths and receipts.
5. Status badges show workspace kind/ref without promoting them to intention
   identity.

* Open Questions
:PROPERTIES:
:ID: magpi-intention-workspace-open
:TYPE: research
:END:

These are deferred choices, not excuses to merge questions:

1. May one attempt attach to multiple intentions? Default *no*; use evidence
   links instead.
2. Is reassignment of =intention_id= allowed post-launch? If yes, journal an
   explicit event; never silent edit.
3. Should read-only attempts share root even when writers are isolated?
   Default *yes*.

:ID: magpi-intention-workspace-summary
:TYPE: decision
:END:
